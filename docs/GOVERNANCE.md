# GOVERNANCE — wine-proton 運用憲章

制定: 2026-11-17（ユーザー立法）。本ファイルが正本。改定はユーザー承認が必須。

## R1 — 上流吸収未確認の patch 無効化禁止

patch の無効化・削除は、上流（Wine / Wine-Staging / GE）への吸収または
代替の確認を条件とする。確認は推測ではなく証拠で行う。

- 必須証拠: 対応する上流 commit hash、または適用対象消滅の具体的根拠
  （対象ファイル・シンボルの不在など）。
- 証拠なき無効化は禁止。`disabled/` への移動も同条件。
- 監査証跡は series.conf または commit message に残す。

## R2 — 作業場は hdd 正本のみ

正本ツリー: `/mnt/hdd/repo/proton-ge-custom`。
他の checkout（home 側等）は参照専用であり、成果の取り込みは行わない。

- 他ツリー基準の失敗リストは、そのまま正本の repair 対象にしない。
  正本ツリーに存在しない対象は「別ツリーのゴースト」として別タスク化する。
- 正本に存在しない flat/patchset は repair 対象なしと確定し記録する。

## R3 — 移植優先・削除は同等性証明後

方針選択の優先順位: 移植 (port) > 削除 (drop)。

- 削除は、同等性証明（上流吸収・代替機能の確認）の後にのみ選択できる。
- 移植が必要な残件は将来作業としてタスクに残し、黙って落とさない。

## R4 — repair のみ・見せかけの緑禁止

`--check` の緑化は repair（適用修復）のみで行う。

- 削除・無効化・テスト緩和・テスト削除による緑化は禁止。
- 修復不能な赤は既知ベースラインとして記録し、対応タスクへ移管する。
- 条件付完了の場合は、何が緑で何が既知赤かを明示する。

## R5 — ユーザー指示は方向レベルのみ

ユーザーの指示は方向（何を目指すか）にとどめ、手段の判断は agent が行う。

- agent は方針・手順・分割を自律的に決定し、記録する。
- 真に曖昧で推測不能な点（認証情報・外部判断・対価を伴う選択など）のみ
  ブロックして人間に問う。推測可能な点は問わない。

## R6 — 追従は 10〜20 件規模を想定し機械化する

上流追従・残差修復は 1 件ずつ手作業せず、10〜20 件規模のバッチ処理を想定する。

- 共通方針（対象 REPO・`--check` 受入基準・repair のみ・作業分離）を先に固定し、
  子タスクへ展開して並列に処理する。
- 件数の過不足は割付時に検算する（例: 8+8+8+8+13+3=48）。

## R7 — 解決は全件 docs/KB に記録する

解決した事項は全件 `docs/KB/` に記録する。記憶・口頭・申告だけの done は認めない。

- 記録単位: 1 件 1 ファイル。実 exit・実 artifact（ログ・commit hash・件数）を添える。
- 未解決の残件も「将来作業」として記録し、行方不明にしない。
- ファイル名規約: `<YYYY-MM-DD>-<topic>.md`。

## 運用規約

- 1 concern 1 commit。commit message は英語・imperative・短文。
- 作業は自分のタスクの worktree/正本のみ。他人の branch に触らない。force-push 禁止。
- 同じ失敗が 3 回続いたら `blocked:` + 証拠を残す。
- done の宣言は証拠（実 exit・実 artifact）で裏付ける。
